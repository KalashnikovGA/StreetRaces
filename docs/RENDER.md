# Пайплайн машин

Две разные задачи, которые легко перепутать:

| Что | Чем | Куда кладётся | Состояние |
| --- | --- | --- | --- |
| Модель для витрины в гараже | `scripts/prepare-car-model.mjs` | `public/models/<id>.glb` | работает |
| Слоёные 2D-спрайты для заезда | `scripts/render_layers.py` (Blender) | `assets/sprites/<id>/` | написан, не прогонялся |

## Незыблемое правило

**Камера настраивается один раз и больше не меняется никогда.** Всё совпадение
слоёв держится на этом. Сдвинулась камера — вся ранее отрендеренная библиотека
несовместима с новыми деталями.

Параметры лежат в `assets/render/camera.json` и версионируются в git. Менять
только с явного разрешения человека и только вместе с полным перерендером.

## Модель для гаража

```bash
node scripts/prepare-car-model.mjs <вход.glb> <id-машины> [--cell 0.018]
```

Скрипт выбрасывает то, чего при виде сбоку не видно (салон, двигатель) и то,
чего не должно быть по юридическим причинам (шильдики, таблички
производителя), снимает текстуры, сливает всё в четыре меша с материалами
`body`, `glass`, `wheel`, `light`, децимирует и ставит машину колёсами на ноль
носом в +X — туда же, куда смотрят процедурные плейсхолдеры.

Материал обязан называться `body`: по этому имени гараж красит кузов. Цвет —
параметр, а не файл: 50 окрасок это 50 строк конфига (§11).

Ячейка `--cell` — сторона решётки децимации в метрах. Меньше значит детальнее
и тяжелее. 0.018 даёт около 59 тысяч треугольников и мегабайт на машину;
0.028 роняет вес до 750 КБ, но по кромкам бампера начинают лезть дыры.

Машины, у которых есть настоящая модель, перечислены в `REAL_MODELS`
в `scripts/build-car-models.mjs` — генератор плейсхолдеров их не трогает.

## Силуэт для заезда

Заезд рисуется вектором по контуру из `SILHOUETTES` (`src/render/car.ts`).
Контур снимается с той же модели: ортографический рендер строго сбоку,
альфа-канал, верхний профиль по колонкам, упрощение Рамера—Дугласа—Пекера
до десятка якорей, потом пересчёт в доли габарита.

Так силуэт на трассе и модель в гараже остаются одним объектом, а не двумя
картинками, которые разъедутся при первой правке. Остекление достраивается
по линии крыши руками: в исходниках стеклом называют и фары тоже.

## Слоёные спрайты (шаг 8)

```bash
blender -b assets/render/scene.blend -P scripts/render_layers.py -- --car <id>
```

Сцена ждёт коллекции с именами `<id>_body`, `<id>_wheels`, `<id>_glass` и так
далее по списку `layers` из `camera.json`. Скрипт скрывает всё кроме целевой
коллекции, рендерит PNG в `assets/sprites/<id>/` и пишет `layers.json`
с порядком наложения.

Кузов рендерится **белым**, `body_shade` кладётся поверх отдельным слоем.
Слой винила принимает произвольную текстуру, а не набор пресетов — это
единственное, что Sponsored Car требует от пайплайна заранее (§8).

### Порядок работы, не нарушать

1. Одна машина, один слой (`body`). Показать человеку.
2. Дождаться подтверждения, что камера и свет верны.
3. Добавить остальные слои этой машины, проверить совпадение в браузере:
   колёса должны стоять в арках.
4. Только после этого — пакетный прогон библиотеки.

Оценить рендер может только человек. На первых итерациях камера и свет почти
наверняка потребуют правок.

### Чего не хватает

`assets/render/scene.blend` в репозитории нет, и сам скрипт ни разу не
запускался: Blender в среду разработки не установлен. Синтаксис проверен,
логика — нет. Первый прогон на живом Blender почти наверняка потребует правок
по расстановке света и `ortho_scale`.
