# «На слабо» — браузерная гоночная игра

Наследник «Уличных гонок» (Ciliz, ВКонтакте, 2010). Социальный симулятор
стритрейсинга: игрок не управляет машиной в заезде, он принимает решения до старта.

Полная спецификация — [`docs/SPEC.md`](docs/SPEC.md).
Решения, принятые в обход спецификации, и их основания — [`docs/DECISIONS.md`](docs/DECISIONS.md).

## Посмотреть

```bash
npm install
npm run dev
```

Вкладки те же и в том же порядке, что в оригинале.

- `/` — **Гонки**: светофор, вид сбоку, звук, финиш. Кнопка «Другой заезд» пересобирает
  соперника. Ссылка под заездом — это повтор: весь заезд лежит в ней, она открывается
  у кого угодно без регистрации.
- `/garage.html` — **Гараж**: машина с цифрами, ряд запчастей с уровнями, места в гараже
  списком, последние гонки, сводка за карьеру.
- `/shop.html` — **Автосалон**: витрина модели и список площадки с ценами; классы выше
  своего видно, но взять нельзя.
- `/pimp.html` — **Pimp**: окраска, номер, свет в боксе. На заезд не влияет ничего.
- `/sandbox.html` — песочница баланса: ползунки характеристик, настройка, условия, сид.
  Прогон пачки заездов показывает, сходится ли эмпирика с формулой.

Гараж, салон и Pimp работают на витринном состоянии в памяти вкладки
(`src/ui/state.ts`) — до шага 4, когда источником истины станет сервер.

В игре две машины: те, для которых есть модели и отрендерены спрайты.
Остальные точки лестницы классов лежат в `LADDER_MODELS` и нужны только
балансовому прогону — в гараже и салоне их нет.

## Проверить

```bash
npm test        # тесты ядра: детерминированность, формула, раскадровка, повтор
npm run balance # симуляция баланса, ~1.5 млн заездов, проверки из §3, §4, §14
npm run typecheck
npm run build
```

`npm run balance` печатает таблицы из спецификации рядом с тем, что реально даёт код,
и падает с ненулевым кодом, если хоть одна проверка разошлась. Объём выборки меняется
переменной `N` (по умолчанию 300 000 заездов на класс):

```bash
N=20000 npm run balance   # быстрый прогон
```

Главное требование ядра (§3): `race()` детерминирована, весь случай приходит из сида.
Это даёт повторы по ссылке весом в несколько байт, серверную валидацию той же
функцией и воспроизводимость при отладке баланса. Тест «в ядре нет Math.random»
следит за этим буквально.

## Дизайн

Направление и правила — в разделе «Дизайн» файла `claude.md`, решения по интерфейсу —
в `docs/DECISIONS.md`. Коротко: бетон и натриевый фонарь, нулевые скругления, числа
вместо полосок, плотность важнее воздуха. Машина везде показана строго сбоку —
и в заезде, и в гараже, — одними и теми же спрайтами из пайплайна
(`docs/RENDER.md`). Структура экранов взята со скриншотов
оригинала — расположение блоков, плотность и порядок информации. Графика оттуда
не берётся: конкретные изображения охраняются, структура интерфейса — нет.

## Юридическое

Реальные марки не используются: вымышленные имена с узнаваемым силуэтом (§21).
До запуска платежей обязательна консультация юриста по списку из §22.
Обратного обмена монет в деньги не должно быть ни при каких условиях.
